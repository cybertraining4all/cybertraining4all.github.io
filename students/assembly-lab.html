Quick start

  1. Pick a lesson from the Lesson menu (start with Lesson 1). Read the short explanation above the code.
  2. Press ▶ Step (or F10) to run one instruction. The highlighted line is the one that will run next.
  3. Read What just happened? — it explains the instruction in plain English with the real numbers.
  4. Watch the yellow highlights on registers, flags and memory to see exactly what changed.
  5. Made a mistake or want to see it again? Press ◀ Back to undo a step. ↺ Reset starts over.
  6. ⏵ Run executes continuously (adjust the speed slider); it pauses at breakpoints. Click it again to pause.
  7. Click ✎ Edit code to change the program, then Assemble & Load (Ctrl+Enter).

Suggested exercise: before every Step, predict what will change. Then press Step and check. That habit is the fastest way to learn how a CPU thinks.

What is a register?

The CPU can only do math on values that are inside it. Registers are its tiny built-in storage boxes — much faster than memory, but there are only a few. On the 16-bit Intel 8086 (the ancestor of today's PCs), each register holds 16 bits: a number from 0 to 65,535 (or −32,768 to 32,767 if treated as signed).

RegisterNameTypical job
AX (AH/AL)AccumulatorMain math register. MUL and DIV always use it. DOS services read AH.
BX (BH/BL)BaseOften holds a memory address, e.g. MOV AL, [BX].
CX (CH/CL)CounterLOOP counts down with CX. Shift counts can come from CL.
DX (DH/DL)DataHigh half of MUL results, remainder of DIV, address of text to print.
SISource IndexPoints at data you are reading (walking through an array).
DIDestination IndexPoints at data you are writing.
BPBase PointerUsed to reach data stored on the stack (function arguments).
SPStack PointerAddress of the top of the stack. Changed by PUSH, POP, CALL, RET.
IPInstruction PointerAddress of the next instruction. Moves forward automatically; jumps change it.

AX, BX, CX and DX can be split into two 8-bit halves: High and Low. For example, if AX = 0x1234 then AH = 0x12 and AL = 0x34. Writing to AL changes only the right half of AX.

Flags

After most math instructions, the CPU records facts about the result in single-bit flags. Conditional jumps read these flags to make decisions.

FlagMeaningExample
ZF (Zero)The result was exactly 0.SUB AX, AX → ZF=1
CF (Carry)Unsigned result didn't fit (carry out of the top), or subtraction needed a borrow.8-bit 200+100 → CF=1
SF (Sign)Top bit of the result (1 = negative when read as signed).0 − 1 → SF=1
OF (Overflow)Signed result didn't fit.8-bit 127+1 → OF=1

MOV, PUSH, POP, jumps, NOT and XCHG do not change flags. INC and DEC change ZF/SF/OF but never CF.

Memory, addresses and [brackets]

Memory is a long row of 65,536 bytes, each with an address (0x0000–0xFFFF). The Memory panel shows 256 of them at a time in hexadecimal.

You writeMeaning
MOV SI, numbersPut the address of the label numbers into SI.
MOV AL, [numbers]Read the byte stored at that address.
MOV AL, [SI]Read the byte at the address held in SI.
MOV AX, [BX+SI+2]Address = BX + SI + 2. Only BX, SI, DI and BP may be used inside [ ].
MOV BYTE [BX], 5When nothing tells the CPU the size, say BYTE (8-bit) or WORD (16-bit).

Little-endian: a 16-bit word is stored low byte first. MOV [total], AX with AX = 0x1234 writes 34 then 12.

The stack

The stack lives at the top of memory and grows downward. PUSH AX does SP = SP − 2, then stores AX at [SP]. POP AX loads [SP] into AX, then SP = SP + 2. CALL pushes the return address and jumps; RET pops it back into IP.

Instructions, registers and labels are not case-sensitive. Data is placed in memory starting at 0x1000; code starts at 0x0100.

How this differs from a real 8086

  • Instructions are not converted into real machine-code bytes. Every instruction counts as 2 bytes so IP moves in steps of 2 (real x86 instructions are 1–6 bytes long).
  • Segment registers (CS, DS, SS, ES) are not simulated — memory is one flat 64 KB space.
  • Only the 4 most useful flags are shown (the real FLAGS register also has PF, AF, DF, IF, TF).
  • The instruction set is a teaching subset; everything else on this page behaves like the real CPU.
